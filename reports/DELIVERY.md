# VibeI18n delivery report

Verified locally on 2026-10-28. Package: `@usevibejs/i18n` 0.1.0. Product: **VibeI18n — Every Language. One Framework.** The implementation is committed locally; no package was published, no remote was created or pushed, and no service was deployed. Sibling repositories were inspected without changing their tracked files.

1. **ICU/Intl engine.** `intl-messageformat` **12.1.4** and its matching `@formatjs/icu-messageformat-parser` **3.5.22**, verified through registry metadata and installed manifests. Native ECMAScript Intl owns plural/ordinal rules, numbers, currencies, dates, relative time, lists and collation. No custom ICU parser, manual plural engine, eval or Function constructor. [Engine investigation](../docs/research.md), [FormatJS API](https://formatjs.github.io/docs/intl-messageformat/), [Unicode locale conventions](https://unicode.org/reports/tr35/).

2. **Architecture.** Five boundaries are implemented: `src/runtime` for ICU/Intl and bounded caches; `src/core` for framework-independent resources and locale transitions; `src/adapter` for native Vibe reactivity/context/browser integrations; `tooling` for catalog analysis/CLI/Vite; and `compositions` plus `examples` for optional UI/ecosystem integration. Router integration has its own entry point. Node/compiler tooling is absent from browser runtime output.

3. **Public API.** Main exports include createI18n, useI18n, defineMessages, defineLocale, createLocaleContext, provideI18n, useLocale, useDirection, formatter composables, locale utilities and opt-in browser utilities. An instance provides t, dynamic, rich, locale, requestedLocale, availableLocales, fallbackLocale, isLoading, error, dir, ready, setLocale, preload, register, n, d, dateRange, rt, list, compare, install, use and dispose. Implemented subpaths: `/core`, `/router`, `/tooling`, `/vite`. [Reference](../docs/reference.md).

4. **Native reactivity.** The adapter uses public shallowRef/computed/injection/scope/app cleanup APIs from Vibe.js **0.1.0**. app.use and useI18n execute in real compiled .vibe components. Namespace revision signals avoid invalidating unrelated translations. Locale changes preserve component/form/table/dialog state. Mounted independent apps and nested providers are tested, including descendant injection and actual application unmounting. No private UI imports or framework patches.

5. **Catalogs/namespaces.** UTF-8 TypeScript/JSON, nested and flat dot keys, plus explicit `namespace:key` syntax. Resources are snapshotted; flattened duplicate keys and unsafe structures are rejected. Registration replaces by default; explicit merge uses incoming values on collisions. Namespaces load independently. Sole-default loader wrappers are reserved for module exports; see the documented raw-catalog distinction. [Catalog guide](../docs/core.md).

6. **Types.** Literal catalogs infer keys and simple placeholders. Traversal is bounded to eight object segments, twenty placeholders and bounded whitespace trimming. Complex ICU and JSON parameter types come from AST generation: numeric plural/ordinal/number values, string select values, Date/number dates and ordinary Value arguments. Flat generated schemas support large catalogs and namespace keys. Real .vibe negative fixtures reject unknown keys, wrong placeholders and string plural counts. Packed-consumer schema augmentation and invalid calls are also checked. Declarations are emitted by TypeScript, without declaration bundling. [Guarantees and escape hatches](../docs/type-safety.md).

7. **Fallback/loading.** Canonical Intl.Locale tags, explicit fallback maps, structural script/region/variant parents, optional language fallback and loop prevention. No regional sibling guessing. Loading deduplicates requests, caches successful resources, supports preloading/reload/retry and accepts dynamic-import modules. Active locale stays unchanged while loading; only the newest successful request activates. Resource versions prevent a late loader from overwriting an explicit newer registration. Disposal aborts willing loaders and ignores late completion.

8. **Formatting.** Named ICU arguments, nesting, exact plurals, offsets, selects, ordinals, escaping, number/date/time styles and skeletons are exercised. Native number/currency/date/time/range/relative/list/collation helpers accept Intl options and cache instances. Timezone configuration applies to helpers and ICU; currency stays independent of locale. Date-only business values remain application-owned. Range formatting has a documented endpoint fallback. No relative-time timers are created.

9. **Direction/document integration.** Reactive direction uses platform locale metadata and a script-based fallback. Explicit overrides, nested Arabic/Hebrew previews and Vibecn DirectionProvider bindings are implemented. Document lang/dir synchronization is opt-in, checks ownership conflicts and restores attributes safely. Widgets can synchronize only their own root. en-XB testing needs an explicit RTL override because English metadata is LTR.

10. **Routing/persistence.** The optional adapter uses Vibe's existing beforeResolve/afterEach hooks: prepare catalogs, then activate only successful navigation. Path suffix, query and hash survive language changes; cancelled/aborted/failed navigation cannot activate stale catalogs. The connected URL is authoritative. Persistence accepts a custom adapter or guarded localStorage, supports cross-tab changes, serializes writes, suppresses echoes and permits application-chosen initial precedence. The showcase uses route > saved preference > English. [Advanced guide](../docs/advanced.md).

11. **Tooling.** Functional `check`, `generate`, `compile`, `pseudo` and `extract` commands with JSON configuration, CI exit codes and path/key diagnostics. Validation covers JSON syntax/duplicates, resource structure, missing/extra keys and namespaces, invalid/unsupported locale identifiers, ICU syntax/other branches and argument mismatches. Types and precompiled ASTs use the actual parser. Rich precompilation is explicit. Extraction uses public Vibe SFC/template ASTs and Oxc; dynamic calls remain explicit references. The Vite plugin validates real builds and hot updates without compiler patching. [Tooling guide](../docs/tooling.md).

12. **Vibecn switcher.** The original copy-and-own LanguageSwitcher composition reuses installed **Vibecn 0.3.0 Combobox parts**. Native-language labels, search, keyboard selection, active indicators, loading, retries and lifecycle cleanup are verified in Chromium. The same distributable file is compiled in the showcase. No Vibecn runtime dependency is added to the library. The published Vibecn registry does not include this composition; no published `add language-switcher` command is claimed. [Composition](../compositions/README.md).

13. **Ecosystem.** VibeForm **0.1.1** and VibeTable **0.1.1** run in the showcase with localized errors/labels/cells and preserved state. Tested optional examples use VibeQuery **0.1.1** QueryClient caching/invalidation, VibeUse **0.1.1** storage ownership, and VibeAuth **0.1.1** public error-ref typing with allowlisted error codes. These are dev/example dependencies, not library runtime imports. Authentication UI is a local preview and sends no credentials. [Examples](../examples/integrations), [guide](../docs/ecosystem.md).

14. **Showcase/docs.** Ten independently loaded example catalogs: English, Français, Deutsch, Italiano, Português (Brasil), Русский, Español, Türkçe, 한국어 and 日本語. Dashboard navigation, customer search/sorting/pagination/selection, profile editing/validation, currency/date cards, calendar, notifications, invitation dialog, account-flow labels, ICU comparisons and pseudolocalization stress previews work locally. The responsive documentation interface has search, safe text/code rendering, copy controls and light/dark mode. Arabic/Hebrew contexts and a second app demonstrate isolation. Demonstration translations are explicitly not human-reviewed. Run `pnpm dev`.

15. **Actual gates.** Final `pnpm check` exited **0**: strict source/example type checking; real .vibe negative type fixtures; oxlint; oxfmt including .vibe associations; **10 valid catalogs**; **50 unit/integration tests across 8 files**; **14 Chromium browser tests**; tsdown JavaScript/TypeScript declaration builds; showcase/documentation build; and external npm tarball installation, runtime imports, actual CLI execution, generated-schema type checking and browser bundle inspection. Browser tests include out-of-order loading, retry, persistence, state preservation, all ten locales, RTL, malicious-looking interpolation, mobile layout and independent-app unmount. No tests were skipped or type errors suppressed outside intentional negative fixtures. Firefox/Safari and exhaustive accessibility certification were not performed.

16. **Measured results.** See [package measurements](package.json) and [benchmark observations](benchmark.json). Tarball **52,245 bytes**, unpacked package **191,383 bytes**. A minimal external browser consumer is **56,433 bytes / 17,855 bytes gzip**, including ICU and required Vibe reactivity; no Node/Vite/compiler/extraction/JSON-validation modules are retained. A pure direction-helper consumer is **535 bytes gzip** and excludes Vibe/FormatJS. These figures include consumer build overhead. The complete showcase entry is **321.97 kB / 105.14 kB gzip**, CSS **61.55 kB / 12.43 kB gzip**, with nine non-English locale chunks **3.21–4.25 kB** each. On Node **24.22.1**, macOS arm64, the warmed single-process benchmark observed about **0.248 µs** per simple translation, **1.468 µs** per ICU translation, **0.649 µs** per cached number operation and **7.90 ms total** for 1,000 cached core locale switches. Message-cache hits/misses: **101,998 / 2**; formatter hits/misses: **152,997 / 3**. The observed heap delta is ordinary allocation data, not retained-memory/leak evidence. These are local observations, not portable performance guarantees or browser/network switch timings.

17. **Limits.** Full ICU parameter inference requires generated/explicit schemas; dynamic runtime catalogs cannot manufacture static guarantees. Rich output is inert tokens, not arbitrary framework components or HTML. Extraction does not perform alias/import dataflow, arbitrary wrapper analysis, v-for/slot-declaration analysis or source rewriting. CLI catalogs/configuration are JSON; TypeScript catalogs are supported at runtime. CLI watch mode, automatic instance-preserving catalog HMR and a custom language-server plugin are not implemented; supported Vite validation and the ordinary Vibe mapper are used. Pseudolocalization includes a visual stress frame, not an automatic geometric overflow audit. Existing upstream primitives may retain fixed English secondary accessibility labels where no localized prop exists; the showcase disables configurable fixed controls where practical. Live authentication/backend/profile services are consumer-owned. SSR/hydration and a general public render-function API are unavailable in the targeted Vibe.js release. .vibe checking depends on the pinned TypeScript **7.1 nightly** required by that framework's public mapper. Preparsed ASTs avoid parsing those messages but the default intl-messageformat entry still ships its parser. Full host Intl data is required. Catalog retention is instance-scoped and application-controlled; message/formatter caches are bounded. [Security/performance details](../docs/security-performance.md).
